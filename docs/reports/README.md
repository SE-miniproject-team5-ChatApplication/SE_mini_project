# Test reports (Part 3)

| Report | What it shows |
|---|---|
| [Unit Test Report](UNIT_TEST_REPORT.md) | Every unit test in `server/tests/unit/` and its result |
| [System Validation Report](SYSTEM_VALIDATION_REPORT.md) | All 42 Test Plan cases: requirements, automated tests, result and evidence, plus the non-functional requirements |
| [Code Coverage Report](CODE_COVERAGE_REPORT.md) | Statement, line and function coverage of `server/src`, per file |
| [Branch Coverage Report](BRANCH_COVERAGE_REPORT.md) | Branch coverage per file, and the branches no test reached |
| [HTML coverage report](coverage/index.html) | The same coverage, line by line (open `coverage/index.html` in a browser) |

All five are generated by one command, with MongoDB running:

```bash
npm run reports --prefix server
```

It runs every server test once with coverage, then rewrites these files. Run it again after any
code change, and commit the result. The overall results and exit criteria are in
`docs/TEST_SUMMARY.md`.

On Windows, `TC-SAFE-02` fails because Windows has no Unix file permissions; the reports say so,
and it passes in CI on Linux.
